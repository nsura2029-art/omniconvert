Security & Compliance

Private file conversion, clearly documented.

OmniConvert is designed for temporary processing, secure transfer, and a business model that does not sell or mine uploaded customer files.

Current status

This is a sandbox prototype. Production retention, DPAs, infrastructure controls, and independent audits should be finalized before enterprise deployment.

Processed only

Files exist to complete the conversion job requested by the user.

Removed after

Temporary files should be deleted according to the published retention policy.

Not sold

Customer files are not sold, leased, or used for advertising data mining.

File storage Data isolation Secure transfer Privacy & GDPR Enterprise readiness
⌁

File storage & retention.

Input files, intermediate files, and converted outputs should be kept only for the time required to process the conversion, provide download access, and recover failed jobs.

The production service should publish exact retention windows and give users a clear way to remove stored results when account storage exists.

□

Data isolation.

Each conversion job should be scoped to the requesting user or session. The conversion queue, logs, and output links should not expose files across accounts or anonymous sessions.

✓
Separate job identifiers for every conversion request.
✓
Download access bound to the user, session, or signed result link.
↔

Secure transfer.

Production uploads, downloads, account sessions, and cloud-storage callbacks should run over HTTPS/TLS with current ciphers. Public endpoints should avoid exposing raw storage paths.

○

Privacy & GDPR.

OmniConvert should maintain a clear privacy policy, subprocessors list, regional processing notes, and data subject request process before serving regulated teams.

For business customers, a data processing addendum should be available once production infrastructure and subprocessors are finalized.

✓

Enterprise readiness.

ISO 27001, SOC 2, and similar certifications should not be claimed until independent audits are complete. Until then, the security page should label these items as roadmap work.

✓
Documented access controls and activity logs.
✓
Incident response, vulnerability management, and secure development practices.

Trust should feel simple.

No overclaiming, no noisy badges, no dense card wall. Just the security model, the retention promise, and the compliance work still ahead.
